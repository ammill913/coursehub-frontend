# CourseHub Frontend

Фронтенд для перегляду каталогу курсів CourseHub. каталог курсів, викладачів і факультетів з реєстрацією, входом за JWT та правами доступу за ролями. Написаний на HTML, CSS і чистому JavaScript, без збірки й залежностей.

## Що вміє

| Сторінка | Файл | Хто бачить |
|---|---|---|
| Курси (пошук за назвою, фільтр за факультетом) | `index.html` | усі |
| Викладачі | `teachers.html` | усі |
| Факультети | `faculties.html` | усі |
| Реєстрація | `register.html` | лише гості |
| Вхід | `login.html` | лише гості |
| Профіль: дані акаунта, права, стан токенів | `profile.html` | лише авторизовані |
| Керування каталогом: додавання, редагування, видалення | `manage.html` | лише авторизовані; видаляти можуть тільки адміністратори |

### Поведінка

- Неавторизований користувач, який відкриває `profile.html` чи `manage.html`, потрапляє на сторінку входу (`login.html?next=...`). Після входу його повертає на сторінку, з якої перенаправило.
- Авторизований користувач не може відкрити сторінки входу та реєстрації: його перенаправляє на сторінку з курсами.
- Гість бачить у шапці кнопки «Увійти» та «Реєстрація» і не бачить кнопки «Вийти». Авторизований користувач бачить своє імʼя, роль і кнопку «Вийти» та не бачить кнопки входу.
- Реєстрація перевіряє дані на сервері. Помилки показуються під відповідними полями. Після успішної реєстрації користувач одразу входить в акаунт.
- Вихід видаляє збережені токени (`localStorage`) і повертає на головну сторінку.
- **Оновлення токена.** Access токен живе 5 хвилин. Коли сервер відповідає `401`, фронтенд сам надсилає refresh токен на `/api/auth/refresh/`, зберігає новий access токен і повторює запит. Користувач цього не помічає. Якщо refresh токен теж закінчився, сесія очищується і користувача перенаправляє на сторінку входу. Цей процес можна побачити на сторінці «Профіль»: кнопка «Симулювати закінчення токена» псує access токен і робить запит.
- Сторінка «Керування» дозволяє додавати та редагувати курси, викладачів і факультети будь-якому авторизованому користувачу. Кнопка «Видалити» є лише в адміністраторів. Помилки сервера (наприклад, `409` при видаленні факультета з курсами) показуються користувачу.

### Структура

```
index.html, teachers.html, faculties.html, login.html,
register.html, profile.html, manage.html, style.css
js/config.js    адреса бекенду
js/api.js       токени, запити до API, автоматичне оновлення access токена, редіректи
js/layout.js    шапка з кнопками входу/виходу, допоміжні функції DOM
js/*.js         скрипти окремих сторінок
```

## Адреси та порти

| Сервіс | URL | Порт |
|---|---|---|
| Frontend | `http://127.0.0.1:3000/` | `3000` |
| Backend API | `http://127.0.0.1:8000/api/` | `8000` |

## Як запустити проєкт

### 1. Бекенд

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```
Для входу створіть користувача через реєстрацію; для ролі адміністратора виконайте в бекенді `python manage.py createsuperuser`.

### 2. Фронтенд
Запустіть:
```bash
python -m http.server 3000
```
### 3. Відкрийте `http://localhost:3000`.

| Що | Адреса |
|---|---|
| Фронтенд | `http://localhost:3000` |
| Бекенд (API) | `http://127.0.0.1:8000/api/` |
